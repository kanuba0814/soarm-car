# DC1 办公室：多算法与多时间采样实测

2026-09-15，指定 worktree 内完成 12 次实验（8 次稠密前端、4 次 RTAB-Map），全部完整处理输入、正常退出。结论：**联合 RGB 光度与深度几何残差，比单纯光度更值得继续；当前数据未显示三算法主备选择或隔帧多采样的明显额外收益。尚不能据此宣布获得可靠完整 SLAM。**

## 实际测试设置

输入复用 ORB-SLAM3 实验的两个办公室 bag 无损抽帧及同一份唯一 RGB/深度配对，1275 和 740 对。保留已记录的裁剪/标定假设：RGB 顶部 400 行匹配 640×400 深度，深度毫米转米，不拉伸深度。几何标定未完成、无 IMU/轮速/轨迹真值。

OpenCV 4.5.4 的 RgbdOdometry、ICPOdometry、RgbdICPOdometry 是三种帧间里程计，不是三套完整 SLAM。稠密实验输入为等比例 320×200，RGB 用面积缩小、深度用最近邻缩小，K 同比缩放；0.3–5 m 深度，最大深度差 7 cm。四层金字塔迭代数 7/7/7/10，默认像素采样比例 7%，随机种子 17，OpenCV/OMP/BLAS 单线程。完整参数保存在每个 config.json。

RTAB-Map 0.23.7 使用 640×400、GFTT/ORB 特征、Frame-to-Map 里程计，并在有效里程计时按输入时间每秒处理一次完整建图后端，保存 map.db。明确设置 min/max depth=0.3/5 m；默认策略不自动重置，另做外部“连续失跟超过 3 s 后重置里程计并 triggerNewMap”对照。后者每次更换地图并标 map_epoch，不把未观测的位移补成连续轨迹。

全部调用真实 C++/Python 库，没有 ROS 消息回放的额外传输丢帧。源图像解码不计入算法耗时。部分稠密与 RTAB 实验同时执行，耗时受主机调度影响；分辨率和任务不同，不能用这些时间直接横向排名，更不是板端实时认证。

## 稠密前端结果

表中两组数字依次为 `212016` / `212121`。

| 方法 | 算法返回成功 | 通过一致性筛查 | 最长连续通过时间 | 单向算法 p95 |
|---|---|---|---|---|
| OpenCV RGBD（光度） | 94.82% / 97.43% | 85.95% / 91.75% | 9.90 / 5.24 s | 3.84 / 4.35 ms |
| OpenCV ICP（深度几何） | 99.37% / 98.78% | 98.19% / 94.72% | 21.32 / 6.02 s | 5.33 / 5.13 ms |
| OpenCV RGBDICP（联合） | 99.61% / 99.86% | 98.35% / 97.56% | 29.94 / 9.62 s | 7.92 / 8.86 ms |
| 联合方法，每隔一帧 | 99.06% / 96.75% | 90.27% / 78.05% | 7.15 / 1.95 s | 8.08 / 8.87 ms |

**筛查不是准确率。** 每个相邻帧间估计同时满足：正反向均返回成功；双向组合位姿差 <3 cm、<2°；至少 50% 有效源深度抽样点经变换投影后与目标深度相差 <7 cm；平移速度 <3 m/s、旋转速度 <180°/s。这些是本实验显式启发式阈值，并非硬件规格或行业验收标准。光度残差也有记录，但未作为门控阈值。拒绝边会断开局部轨迹，不插值、不填补位移。

联合方法的正反向检查成本 p95 为 15.63 / 17.55 ms。将门控进一步收紧到双向 <1 cm/<1°、深度一致率 >70%，仍通过 96.39% / 95.81%，说明高覆盖率并非只靠单一宽阈值；但一致性、低残差和可逆性均不能消除共同偏差或退化方向误差。

与 ORB 失败区间交叉检查：当相应帧间至少一端 ORB 非 OK 时，联合方法仍有 97.52% / 95.60% 通过此筛查。**这是“值得研究的候选互补”，不是已证明这些帧的真实运动正确。** 特别是白墙上，几何约束可在切向运动/部分旋转上不足；两个方向都错也可能通过一致性检查。当前没有做完整 Hessian 可观测性/退化特征值门控。

联合方法最长连续通过约 29.94 / 9.62 秒，第二段仍明显碎片化，不能把接近 98% 的帧间通过率解读为全程可靠。

## RTAB-Map 完整系统结果

| 策略 | 跟踪返回有效 212016 / 212121 | 显式重置次数 | 后端处理节点 | 检测到闭环事件 |
|---|---|---|---|---|
| 无自动重置 | 34.43% / 37.16% | 0 / 0 | 17 / 12 | 0 / 0 |
| 失跟超过 3 s 后新建地图 | 59.29% / 58.65% | 6 / 4 | 32 / 21 | 1 / 0 |

默认前端在首次严重失跟后长期失败，rejections.txt 包含 `Not enough inliers`；第二种策略增加输出覆盖率，但频繁重置仍未解决连续性。两策略里程计耗时 p95 分别约 42.68/43.90 ms、49.85/47.36 ms；后端另计。

本次配置没有优于已有 ORB-SLAM3 的 65.57%/87.84% 状态覆盖率，但不同检测器、恢复政策、地图语义不完全相同，不能推广为“RTAB-Map 普遍较差”。RTAB-Map 的有效状态与上表稠密方法的双向筛查也不是同一指标。第一段新图策略虽检测到 1 次闭环，没有真值验证闭环正确性，不能把此事件当作质量认证。

## 多种采样/算法融合：实际验证了什么

### 时间跨度

将联合方法改为每隔一帧计算，帧间跨度约加倍，通过率从 98.35/97.56% 降至 90.27/78.05%。按相同起终点比较“两段短边组成的路径”与“一段隔帧长边”：短边路径通过率为 97.65/95.66%，长边为 90.27/78.05%。

第一段仅有 1 个长边通过、短边路径不通过的候选区间，第二段为 0；反过来，短边路径通过而长边失败的区间分别有 48/65 个。两条路径都通过时，约 94.60/95.49% 在 3 cm/2° 内相互一致。可见保留短跨度对本录制更重要，盲目混入低频输出没有明显好处。长边独有候选仍缺少正确性证据，未擅自加入轨迹。

### 三算法主备选择

实现了一个可复核的保守选择器：联合方法通过则选它；联合方法拒绝时，要求纯光度和 ICP 两者都通过筛查、互差 <3 cm/<2°，才选择光度结果。这个方法从不平均位姿，也不跨失败边积分。

结果：两段均 **新增 0 个有效帧间估计**。联合方法单独已有的覆盖率就是选择器的覆盖率；三路算法正反向总成本的逐帧求和 p95 约 32.27/35.60 ms，比联合方法单独的 15.63/17.55 ms 多约一倍。它是成本估计，不是实际部署调度延迟。

即使只计算“任意算法通过即可”的候选并集，上限也仅 99.06/98.11%，相对联合方法不到 1 个百分点；这个并集没有可靠选择依据，不能称为融合成果。`selector.csv` 保存了逐帧选择和算法分歧，拒绝时 source=0。

### 多尺度/多像素采样与独立传感器

本次联合方法已经做了四层金字塔和稀疏像素采样，属于同一观测的多尺度优化；没有单独跑不同像素采样比例或多空间分辨率的消融，不能声称找到最佳采样策略。可以继续比较梯度/深度结构引导的采样，但它不会补回缺失的独立观测。

同一 RGB-D 的 ORB、直接法、ICP 共享标定、曝光与深度误差，不能当独立传感器直接平均或重复灌入 EKF。更值得后续验证的结构是：**RGB 光度＋深度残差联合的局部前端 → 连续性/退化门控 → 全局地图后端；IMU/轮速作为新增独立观测接入局部估计；闭环只修正 map 与 odom 的关系。** 现有 bag 没有 IMU/轮速，尚未实现或验证这一多传感器系统。

## 下一步优先级

1. 完成 RGB-D 几何和时间同步检查，并用标记起终点/已知位移或外部真值录制，测量联合前端的漂移与退化误差；先验证高通过率是否有实际价值。
2. 以当前联合前端为候选增加可观测性门控，再测试与全局地图后端配合。优先处理白墙、模糊和大转动；拒绝时保留失效状态，不靠平滑隐藏。
3. 同步补录 IMU、轮速、外参和时间戳，再验证跨传感器融合。多算法一致性作为健康检查，不把算法数量当独立证据数量。

## 复现与证据

在指定 worktree 运行：

```bash
bash scripts/rgbd-comparison/run.sh rgbd-comparison-rerun-01
```

必须使用新输出名；复用前次 ORB 实验的无损抽帧。脚本固定本机实验镜像 SHA256（含 RTAB-Map 0.23.7），不修改相机/导航。镜像保留为 `dc1-algorithms-test:20260915`，用于复现；迁移到其他机器需另准备该镜像。

- `artifacts/perception-dev/dabai-dc1/rgbd-comparison/summary.json`：全部统计。
- `<bag>/<method>/frames.csv`、`config.json`：稠密逐边变换、正反向误差、残差和参数；`segment` 变化处不得连接轨迹。
- `<bag>/rtabmap*/`：每帧状态、拒绝原因、参数、run.log 和 map.db；重置版本 `map_epoch` 变化处属于新图。
- `<bag>/comparison.png`：绿为通过/有效、红为拒绝/失跟。上下图指标不同。
- `<bag>/selector.csv`、`threshold-sensitivity.json`、`manifest.json`：融合选择、阈值敏感性和版本记录。

原 bag 和已有正式 ROS bridge 未修改。新增证据约 29 MB。脚本语法检查、12 份完成标记、逐帧数量以及数据库完整性检查用于验证实验执行；没有把这些检查当成定位精度测试。
