定位及避障继续复用 FAST-LIO/Nav2。研究准确名称是**视觉语义目标驱动的导航**，不是已经实现“纯视觉定位/无激光导航”。不为增加论文工作量而重新实现 SLAM。

## 2. 三个候选方向

### A. 关系约束目标定位与可达观察位联合选择（首选）

例：“去沙发旁边那张小桌子，看看水杯还在不在。”

**方法点 A1：关系与多视角证据约束的视觉目标定位。** 从任务提取目标、属性、空间关系及房间约束；对对象候选图做软约束重排序。将视觉相似度、多帧一致性、关系证据及缺失证据分开记录，不把语言模型自评当校准置信度。关系缺失应保留未知，不能判为满足。与同一视觉编码器的纯相似度检索比较。

**方法点 A2：可达性约束下的观察位选择与终点确认。** 不导航到物体质心；在有证据的 map 变换下产生物体附近候选观察位，先经过底盘 footprint / occupancy / 路径硬约束，再按预期可见性、信息收益与路径代价排序。到位后用新图像确认目标；否定或无证据时进行预算内再观察或明确失败，不能把 Nav2 成功当作找到目标。

研究假设：多同类物体和遮挡场景下，A1 减少错目标；A2 提高可见终点成功率，并降低无效路程。**尚未证明有效或具有足够新颖性**。如果收益仅来自多调用模型或多走路，不能归因为方法本身。

建议先训练自由的检索/排序方案，只在开发集校准权重；若有稳定瓶颈再考虑小规模排序器训练。大模型预训练不是先决条件。

可供下一阶段实现的最小数学形式（提案，不是已实现算法）：

- 候选对象 `o` 的排序分数：`s(o|q) = wv·V(o,q) + wr·R(o,q) + wm·M(o) - wu·U(o)`。`V` 是冻结编码器的相似度，`R` 是已观测关系约束一致性，`M` 是按视角组去相关后的支持度，`U` 是深度/位姿及缺失证据惩罚。连续近邻帧不当作独立支持；用“同一误检连续出现 20 帧”作为必须拒绝虚高置信度的反例。分数不能未经校准就称为概率。
- 在已验证的安全可达集合 `V_safe` 内选 `v* = argmax[α·visibility(v,o) + β·expected_information_gain(v) - γ·path_cost(v)]`。第一版可以用深度遮挡/距离/朝向代理估计可见性，并明确代理不是可见真值；信息收益只用当前观测与地图估计，不能读取仿真隐藏目标标注。
- 先硬筛安全，再做效用排序；任何高视觉得分都不能抵消不可达或几何未知。首选对象的可行观察位集合为空时报告不可达/待核验，不静默换成另一同名对象。
- STOP 需要新帧的目标身份确认与停稳条件；预算耗尽则 unknown/失败。对照组使用同一个终点确认器，避免把确认器差异误算为视角选择收益。

### B. 面向家庭物品移动的时效语义记忆与主动重查

例：“去昨天放杯子的地方找一下；不在就看看旁边。”

方法点：按观测时间、视角覆盖与几何关联质量维护记忆可信度；按不确定性和行走成本选择重查位置。区分“本次没看见”“被遮挡”“已移动”，不以一次漏检删除物体。

基线：静态语义图、仅时间衰减、固定顺序重查。关键指标：错误记忆目标率、重定位成功率、额外距离、错误删除率。需要重复采集**真实不同时间/布局**的家庭场景；现有单段 B06 不能假造跨日变化。数据与身份关联负担较高，建议作为后续课题，而非与 A 同时全部实施。

### C. 面向歧义目标的主动澄清与视觉证据交互

例：“去那张桌子。”机器人根据两张桌子的观测证据问：“靠窗的还是沙发旁的？”

方法点：候选分布驱动的澄清触发与问题选择，可优化信息增益与交互代价；回答只缩小有视觉证据的候选集合，不产生凭空坐标。

基线：不澄清、每次澄清、固定置信度阈值。指标：错误执行率、目标定位率、每任务追问次数和耗时；必须设置同样的拒绝/弃权权限，否则“少执行”会虚增安全表现。语音先固定为文本输入做方法隔离，再测 ASR 噪声鲁棒性。若以该方向为主，应将主动澄清作为唯一重点，视觉导航作为落地场景，而不是再塞入 B 的完整记忆研究。

**推荐选 A，最多两个贡献点 A1+A2；B/C 是备选，不是三个方向一起做。** 暂定题目：《面向家庭服务机器人的关系约束视觉目标定位与可达观察位选择方法》。论文创新声明需继续围绕最相近方法核查，不能仅凭模块组合成立。

原论文与官方实现依据另见 [`companion-visual-navigation-sources.md`](companion-visual-navigation-sources.md)。

## 3. 与当前工作区的接入方式（尚未实现）

```text
聊天/语音转写（工程入口）
  → 区分闲聊与明确任务；闲聊不能触发运动
  → 结构化目标、关系、否定条件
  → A1 视觉候选与证据重排序
  → A2 可达观察位 proposal（地图身份+有效期+证据）
  → 复用现有预览/确认与安全任务执行边界
  → 新视角确认目标 / 预算内重观察 / 失败报告
```

当前房间 API 不接受任意物体观察位，后续需专门的受约束 proposal 接缝；不能把相机系 centroid 偷塞成房间目标。保留 map bundle/room revision、定位新鲜度、停止、取消、显式重新使能及无自动重放语义。几何或路径证据缺失只输出候选，不执行。

GPU 可承担离线视觉特征、检测/分割及候选图构建；Pi/机器人侧保留底层定位、控制和安全链。以后测算端到端 P50/P95 延迟、峰值显存与断联行为后再决定部署划分。家庭图像默认留在受控本地，未经许可不上传第三方 API。

## 4. 验证设计——以下均是未来步骤，不是本轮运行记录

### 阶段 0：冻结协议与几何前提

冻结任务定义、场景划分、物理实例 ID、标注规则、指标与预算。逐项核查 RGB-depth 注册、时间同步、相机内外参、相机位姿到 map 的变换、尺度/单位、地图身份、可达区域。同步与位姿数值平滑不等于精度可靠。

训练/开发/测试按场景或布局组隔离，不能把同一录像的相邻帧随机拆分。人工 test 标注只给评分端，不能提供给检索器或 planner。每个阈值在 dev 冻结后才看 test。最初少量 pilot 只检查可行性，不作为论文最终样本规模。

### 阶段 1：现有录像的离线目标定位

复用现有候选与证据，不先重跑所有视觉系统。人工冻结一个有界任务集，涵盖唯一目标、同类歧义、关系约束、遮挡、移动和不存在；现有数据不支持的类别标为待采集。先比较纯视觉相似度与 A1，报告 Top-1、MRR、弃权率与接受样本上的错目标率。检索率不是导航成功率。

### 阶段 2：现有 ROS/Gazebo 路径的闭环仿真

优先复用当前 house 世界、Nav2 和安全链；先核查模拟 RGB-D、目标资产、相机 TF 和标注可用性，缺失时补齐后才运行。不要默认 Gazebo 已具备语义 benchmark。需要公开规模数据时可考虑 Habitat，但须先核查数据访问许可和到现有 ROS 接口的迁移成本，不同时搭建两套主平台。

对比四组：

| 组别 | 目标定位 | 观察位策略 |
|---|---|---|
| B0 | 同编码器纯相似度检索 | 最近的安全可达观察位 |
| A1 | 关系/多视角重排序 | 同 B0 |
| A2 | 同 B0 | 可见性/信息收益排序及有界重观察 |
| A1+A2 | 完整定位 | 完整观察策略 |

所有组共用视觉输入、检测器、地图、候选生成器、低层控制器及最终确认器；都允许在相同预算内重试。预算包括路程、观察次数、模型调用、时限。增加匹配预算的简单随机/固定次序观察对照，以排除“多看几次就更好”。语义标签真值只能用于额外的 oracle 诊断，不计入可部署方法。

### 阶段 3：实物小规模迁移

先完成现有硬件导航入口与标定/安全验收，再在隔离区域、有人监督和物理急停条件下逐级运行。采用同一视觉编码器和冻结策略，在不同布置、光照及同类目标下做配对比较。仿真成功不证明真机可靠；终点停稳、目标新观测确认与任务报告分别记录。

### 指标与判定

- 导航到位 SR 与视觉目标确认成功率分开；任务成功要求在预定预算内到达合法观察位并用新观测正确确认指定目标。
- 有目标、可达任务使用 SPL：`S * L* / max(L*, L)`；`L*` 为从相同起点到合法成功观察位集合的最短可达路径，不是到物体中心的欧氏距离。无最短路径证据不得报 SPL；起点已成功的零距离情形需预先定义。
- 不存在目标单独测正确拒绝与错误成功报告率，不混入 SPL；不可达、歧义和失败任务不能在事后默默剔除。
- 记录实际路径长度、耗时、终点可见性、错误目标率、碰撞/接管、观察次数、模型调用、追问次数、延迟与显存。
- 相同任务/布局/随机种子配对；按场景聚合与 bootstrap 置信区间，避免把高度相关帧当独立样本。单一场景小试只报告描述性结果，不作泛化结论。
- 若 A1 在关系任务不改善、A2 在等预算下无增益、或收益仅出现在有 GT 泄漏的设置，则假设不成立；保留失败结果并收缩贡献，不追加无关模块掩盖失败。

## 5. 本轮配套工具及停止点

新增 `config/companion-navigation-study.json` 与标准库 CLI `scripts/prepare_companion_navigation.py`：准备实验矩阵、生成缺省阻断的几何证据模板、只读检查证据记录完整性。具体参数以 `--help` 为准。计划中的任务都是 `planned`，不是实测结果；几何文档完整不等于标定正确，也不等于获准运行。

准备命令（不执行实验；输出目录须已存在，输出文件须不存在）：

```bash
python3 scripts/prepare_companion_navigation.py --help
python3 scripts/prepare_companion_navigation.py plan \
    --config config/companion-navigation-study.json --output /tmp/companion-plan.json
python3 scripts/prepare_companion_navigation.py template --output /tmp/companion-evidence.json
python3 scripts/prepare_companion_navigation.py preflight --manifest /tmp/companion-evidence.json
```

模板的 preflight **预期返回 BLOCKED / 退出码 1**，不是工具故障。证据路径相对 manifest 解析；该命令只检查声明、文件存在性/非空和地图 ID 一致性，不读取标定内容判真，更不能充当机器人安全认证。缺少输入/非法 JSON 以非零码失败；写操作不覆盖已有文件。

默认矩阵是 3 个假设场景槽位 × 2 个种子 × 5 类任务 × 4 种方法 = **120 条待补全运行计划**，不是 120 次实验或独立测试任务。每条还需绑定真实场景/布局、目标实例、语言指令、起始位姿、证据与预算，才能转成可执行 episode。相同 `(场景, 种子, 类别)` 的四组方法应共享同一任务定义；其中 moved 类需另采布局变化数据。当前工具没有实现视觉方法、仿真执行器或评分器，避免在方向未确定前写一套无用实验框架。

本轮只允许对**新工具自身**做临时目录中的 JSON/CLI 自检，不进行方法性能评分，不运行模型、仿真、ROS 或实物控制。不安装依赖、不下载数据/权重、不改现有运动控制或权限配置。
