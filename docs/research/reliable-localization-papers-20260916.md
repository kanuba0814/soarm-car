# 仅 DC1 RGB-D 的可靠定位：最新论文与最小验证路线

研究截止：2026-09-16。本文是文献核查和实验设计，**不包含本轮新增算法实测**。最终约束为只使用现有 DC1 RGB-D 相机；不以新增 IMU、轮速、激光或人工标签作为解决方案。本机为 Core Ultra 7 255H、无 NVIDIA GPU。日期以论文提交记录、作者页面为准；没有把搜索结果的抓取时间当发布日期。

## 1. 当前应做的决策

**先验证“原始深度 + 联合局部估计 + 可审计的地图约束”，把目标从帧间通过率转为连续段漂移、真实闭环和跨段恢复。** RTAB-Map 接收已有 RGBDICP 分段里程计，是当前成本最低、最能回答全局漂移问题的工程实验。它是待测组合，并非由论文保证有效的新算法。

已有证据来自 [9/16 数据验收](../dabai-dc1-data-acceptance.md)：两段 DC1 为 1275/740 对唯一 RGB-D；顶部裁剪获得支持，但相机 K 的绝对准确性、深度偏差和曝光同步尚未独立确证。最近时间戳配对保留，原始深度保留。此前无置信度填洞虽把 DC1 接受率提高到约 99.7%，却令冻结 TUM 长序列 ATE 从 47.44 cm 恶化到 71.63 cm。

同一前端在 TUM `fr3/long_office` 接受率为 100%，ATE 仍为 47.44 cm；ORB 单地图对照为 1.50 cm。后者表明当前评估链能测出厘米量级，并不意味着 DC1 也达到该精度。两段 DC1 无轨迹真值，现阶段只能报告一致性、覆盖、失效和恢复，不能宣布“厘米级定位已达成”。

此判断更新了 [9/15 主报告](next-generation-visual-system-20260915.md) 和 [实验矩阵](next-generation-visual-experiments-20260915.md) 的优先级：在现有 CPU 和唯一相机约束下，先处理全局约束及恢复，再考虑学习特征；不继续堆叠补全模型和稠密渲染系统。

## 2. 2026 年新增证据及可复现性

以下只选直接影响当前决策的研究。表内论文指标不移植为本机、本 bag 的性能承诺。

| 工作与核验日期 | 一手证据、公开状态 | 对 DC1 的实际取舍 |
|---|---|---|

| **XFeat Revisited**；2026-08-10；TMLR 2026-08，Reproducibility Certification | 重实现和原 checkpoint 重评支持 XFeat 的匹配效率优势，同时指出 Aachen 定位低于原报告，对未充分说明的评估细节敏感；复现代码公开。[论文](https://arxiv.org/abs/2608.09519)、[复现代码](https://github.com/GalaxyGHz/xfeat-revisited) | CPU 学习路线优先选择已有 CPU 证据的 XFeat，先测少量关键帧匹配、RGB-D 几何验证和耗时；匹配数增加不直接等于定位改善。 |

### 可靠性应从最新论文借鉴什么

《Failure or Drift?》于 2026-08-31 提交，属 ECCV 2026 NeuSLAM **workshop**。其比较显示，继续输出和没有漂移是不同事件；合成扰动的物理合理性会改变算法排序。该研究面向单目和户外退化，不能推出实验室 RGB-D 算法排名；可直接借鉴的是把失跟与错误输出分开评估。[论文](https://arxiv.org/abs/2608.30690)

地图定位还应区分实时结果与闭环后的历史轨迹。《Multi-cam Multi-map Visual Inertial Localization》的 2025 修订研究强调机器人控制需要因果位姿，而常规整段对齐/回溯 SLAM 评估会掩盖实时定位误差。本文只采用其评估观点，不采用多相机惯性硬件路线。[论文及版本记录](https://arxiv.org/abs/2412.04287)

## 3. RTAB 全局后端实验：支持依据与四个盲点

RTAB 官方 `Rtabmap::process` 接口直接接收 RGB-D `SensorData`、外部 `odomPose` 和 6×6 协方差；支持新地图会话。因此可以复用前端而独立检验地图约束。[官方接口](https://github.com/introlab/rtabmap/blob/master/corelib/include/rtabmap/core/Rtabmap.h)

在线文档为当前上游；当前实验镜像为 RTAB-Map 0.23.7，具体参数、编译后端和行为必须以镜像内头文件/运行日志为准，不能假定上游 master 所有功能均存在。

1. **无新增约束就没有全局纠漂来源。** 只有相邻里程计边的链式图可以完全满足原测量，优化不会自动消除累计漂移。首次跨两个独立分量的连接只确定相对坐标，也不提供闭合冗余。分别记录相邻边、同分量非相邻边、跨分量边，不能把全部“loop/proximity”计数混为收益。此条是因子图结构的工程推论。

2. **断边必须真实断开。** 联合前端拒绝一条边时，后续段换 `map_epoch`，不可用单位位姿或上一位姿悄悄补边。RTAB 参数说明特别指出外部 odom 自动 reset 未必触发新地图；应显式开启新会话并检查数据库边表。[官方参数](https://github.com/introlab/rtabmap/blob/master/corelib/include/rtabmap/core/Parameters.h)

3. **跨段首个假闭环最危险。** 官方多会话案例表明，首次合并独立地图时，图变形验证和鲁棒优化仍可能接受相似地点的错误关联；不存在已知路径形成闭合矛盾，低优化残差不足以证明正确。跨段边须另查双向几何、深度一致性、匹配点分布和多个相邻关键帧的变换一致性；这些是新增工程验收条件，仍非独立真值。[官方多会话反例](https://github.com/introlab/rtabmap/wiki/Robust-Graph-Optimization#multi-session-without-gps)

4. **协方差决定后端信谁。** 正反向一致、低光度残差不能直接给出已校准的位姿协方差。单位阵或任意很小/很大常数只可作为明确记录的试验假设。维护者给出 odom 协方差过大令坏闭环难以拒绝的实例；官方传统配置还指出 `Optimizer/Robust=true` 与非零 `RGBD/OptimizeMaxError` 不应并用。先选一条明确的保护路径，记录有效编译配置。[维护者解释](https://github.com/introlab/rtabmap/issues/773)、[官方配置](https://github.com/introlab/rtabmap/wiki/Robust-Graph-Optimization#configuration)

前端局部估计、闭环和稠密检验均来自同一相机，证据存在相关性。不能将三者一致解释成“三个独立传感器证实”，也不能把前端 ICP 残差再次当作唯一成功指标。几何验证应保留未参与位姿求解的像素或关键帧，用于检查过拟合；该留出仍不能给出绝对真值。

## 4. 最小实验集与明确淘汰条件

只安排三组，顺序依赖。原始 bag、唯一配对、裁剪、内参和深度来源固定；不在本轮顺手调所有前端参数。

| 组别 | 唯一要回答的问题 | 实际动作与数据 | 保留/拒绝依据 |
|---|---|---|---|
| **E1：联合前端 + 后端** | 地图约束是否降低累积漂移？ | 复用全部前端输出，在现有 TUM 和两段 DC1 上比较纯累计与 RTAB 优化；拒绝边开新会话。保存原始图、优化图、边类型、节点时间、分量、在线修正。 | TUM 同一节点集合、同一连续段的 SE(3) ATE/RPE 有改善且失效/错误接受未恶化。若没有有效非相邻约束，结论应为未获得纠漂证据。DC1 只评一致性和恢复。 |
| **E2：固定地图重定位** | 第二次访问能否可靠回到第一张地图？ | 先核对两包是否有真实视野重叠；若有，将一包建图后冻结，另一包只作查询，再反向交换。非重叠帧作为拒绝样本。记录首次匹配、几何接受、连续确认、恢复时延。 | 报告正确/可疑/无法判定，不把“检索命中”算重定位。两个短包不能代表长期变化；若缺少重叠，记录不可评估，不强行合图。 |
| **E3：条件性 CPU 学习匹配** | 当前恢复失败是否来自描述子/匹配，而非深度或无重叠？ | 仅当 E2 有明确匹配失败样本，用 XFeat 对同一组关键帧候选做 RGB-D PnP/3D–3D 验证；固定几何阈值和候选预算，对照 ORB。预计算地图描述子，CPU 查询逐次计时。 | 只有错误重定位未增加、可验证恢复增加且查询延迟可接受，才接入异步恢复支路。若仅匹配数增加或深度验证失败，不替换前端。 |

如果 E1 的瓶颈是长时间没有重访、局部累计漂移明显，后续优先验证**帧到局部地图或滑窗约束**。单纯放宽闭环阈值、增加同方向平面点、插值补齐轨迹，都不能补上缺少的观测。局部地图方案会扩大实现范围，应作为下一组独立消融，不能夹进 E1 混淆收益。

### 本轮必须保留的结果契约

1. **完整时间轴：** 输入、初始化、拒绝、失跟、重置、段起止、地图合并分别记录。断点不连线，孤立分量不伪装成同一世界坐标。
2. **精度与覆盖成对：** 有真值时用米制 SE(3) 对齐，禁止用 Sim(3) 尺度修正掩盖深度尺度误差；同节点比较前后误差，另报全输入覆盖。分段结果按预先确定规则汇总，不只挑最佳段。
3. **实时与回溯分开：** 每帧当时发布的 `map→camera` 位姿单独冻结；最终优化图另存。离线回放不能宣称具备相同实时恢复能力。
4. **候选与确认分开：** 保存闭环检索分数、几何内点数/分布、双向残差、优化拒绝原因、跨段变换、接受时刻；恢复前的未知状态不回填成在线成功。
5. **成本与版本：** CPU 线程数、模型/代码哈希、图后端、端到端 p50/p95/p99、峰值内存、队列积压。对结果有新增疑点再扩展复跑，不以无差别扫参制造“最好一次”。

## 5. 能做到和仍不能证明的部分

仅 DC1 路线可以验证局部几何、重复回访的地图定位、错误关联拒绝和失跟恢复。学习特征可改善部分外观变化，但真实无纹理、深度无效或完全遮挡时仍可能没有充分约束；可靠系统需要如实报告未知，而不是保持输出造成假连续。

当前两包都曾用于开发和诊断，互换建图/查询属于同域回归，不能称为独立泛化测试。未来仍可只用同一 DC1 录制更长的重复访问、不同光照、家具变化和遮挡恢复序列；这样能扩展可靠性证据，但没有独立测量依据时，绝对定位精度仍应保留为未验证。

本文未下载模型、未启动硬件，也未将文献方法算作本地已复现。当前最强可执行结论是：**先做 E1，按非相邻约束与真值漂移判定收益；有证据再做 E2/E3。**
