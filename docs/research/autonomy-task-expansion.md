# soarm-car 低人工干预任务扩展：研究证据与毕业设计建议

研究日期：2026-09-08。范围：探索研究，不实现产品。本报告只读研究 `/home/gxxl/soarm-car` 的当前文件，包含未提交的 `soarm_room_navigation`、`docs/room-navigation.md` 与感知脚本；输出仅写入研究者独立 worktree。没有启动 ROS、容器、硬件、远端模型，没有上传本地材料、安装依赖或提交 commit。

## 1. 结论与优先路线

建议毕业设计主线为：**已知地图上的受限语言任务编排与主动观察，以任务级一次授权、确定性执行、证据化完成判定和有界恢复减少人工接管。** 最先扩展无接触任务，再研究抓取。当前最有证据的基础是房间导航、顺序访问、等待、返回起点、有限备选，以及独立的书桌几何搜索流程；不存在足够证据把系统描述成“任意物品搜索抓取配送机器人”。

任务数量应按不同的成功谓词和观察/行动需求统计，不把“去书房”“去卧室”或不同措辞算作多个任务族。建议形成 4 个主要任务族：房间访问、巡检观察、目标搜索、库存与变化核查。抓取/放置作为后续条件成熟后的独立研究阶段。

优先顺序：

1. P0：把已有导航与恢复能力形成可重复的多任务评测，冻结地图、房间目录、任务集和完成判定。
2. P1：增加观察证据和有预算的跨房间搜索，首先复用保守桌面几何与已有离线 RGB-D 产物。
3. P1：评估固定路线与语义优先路线、无记忆与带新鲜度记忆，在相同感知/安全条件下比较干预与成功率。
4. P2：扩展为物品清点、物品位置问答、变化复查；前提是跨帧实例对应与人工评分规则可信。
5. P3：真实抓取、持物移动、放置/交付；它们超出现有 mission policy 的部分边界，本轮只列研究方向，不授权实现。

搜索模块 `core.py:125` 仍只解析 `去 <唯一房间别名> 找书桌`，不接受跨房间开放搜索；`confirm_intent` 与 `confirm_dock` 是两个不同确认点。导航模块文档明确不实现搜索或抓取。二者相邻但没有共同的任务编排入口。

**集成前必须解决的实际接口差异（P，非本轮改动）：**

- 导航目录是 occupancy/PCD/alignment 的 digest 绑定；搜索使用旧的 map identity 方案，不能直接互换 rooms JSON。
- 导航使用方形底盘与任意朝向保守净空；搜索的 footprint 方法使用半径参数。观察候选不能因为在搜索侧通过就绕过导航侧实际底盘验证。
- 搜索 `Workflow.preview` 将 room revision 与常量 1 比较；不能照搬成支持动态房间编辑的共享缓存协议。
- 搜索几何候选与导航任务目标不同：应传已验证的站位引用及输入证据版本，由确定性层解析，不开放模型任意坐标。
- 两个模块都持有 Nav2 goal 的流程，不应同时作为独立运动 owner 运行。未来需要一个执行所有权/取消边界，保持 gate 和真实终态语义。
- `TaskJournal` 用于未完成工作与恢复保护，不是完整实验事件日志，也不能用于重启自动重放。

## 4. 可扩展任务清单与人工干预点

下列“成本”为相对研究工作量，非时间承诺。P0/P1 优先避免接触物体；带观察或语义的任务目前均需要增量开发和评测。

| 优先级 | 任务与独立成功谓词 | 复用/新增 | 自动化收益和人工点 |
|---|---|---|---|
| P0 | 单房间访问：在目标区到达并停稳 | 已有 navigate，低成本 | 开始确认一次；歧义房间询问；停止后人工 rearm |
| P0 | 多房间顺序巡访：所有指定点按顺序完成 | 已有 ≤8 步序列，低成本 | 一次确认替代每房间提交；超出步数拆成明确的新任务，不能偷偷扩容 |
| P0 | 限时驻留后返回：到 A、等待 t、回任务起点 | 已有三种 action，低成本 | 全序列一次确认；“返回”仅位置，不宣称归航/充电 |
| P0 | 可解释的普通失败备选：主目标失败后仅走预览过的替代房间 | 已有一次 fallback，低成本 | 减少普通 abort 的人工改目标；安全失败或备选失败仍停止求助 |
| P1 | 房间观察巡检：各站采到新鲜可用 RGB-D 和位姿证据 | 导航+扫描；新增 observe/记录结果，中成本 | 预先确认区域/视点和采集范围；正常不逐帧确认；模糊帧可有界补采 |
| P1 | 指定房间找水平桌面并停靠观察：验证候选、可达、到位 | 已有独立搜索链；与导航编排接合，中成本 | 现状保留意图确认+最终停靠确认；几何不是语义，名称需保守 |
| P1 | 多房间限时找某类目标：在预算内输出位置与最近观察证据 | 有限房间路线+观察；新增目标匹配/搜索记忆，中高成本 | 开始授权房间与预算；同名多物、低置信度时问一次关键澄清；未见只能报告“预算内未发现” |
| P1 | 目标最后位置查询：回答“上次在哪里看到”，包含时间/图像 | 复用离线结果；新增实例证据索引，中成本 | 纯只读回答无需机器人运动；陈旧记录触发显式“需要复查”，不能冒充当前位置 |
| P2 | 物品清点：指定区域内可见独立物体的一对一列表 | RGB-D/实例评分；新增跨帧去重，中高成本 | 操作中少确认；初次数据标注和最终评分人工时间单独计量 |
| P2 | 前后变化复查：报告新增/消失/移动的可核实实例 | 重访+库存；新增时空对应、遮挡不确定态，高成本 | 遮挡只能“不确定”，必要时自动有限补视角；报告有争议项给人 |
| P2 | 按空间关系查找：“书桌旁的椅子/瓶子” | 房间/物体图+关系验证，高成本 | 关系不唯一或地标缺失时澄清；不能用语言先验直接生成运动目标 |
| P2 | 观察位置替代：首视点遮挡，换预授权安全视点再看 | 候选/路径过滤；新增信息收益评分，中高成本 | 预先给 ≤K 个视点/时间预算；规划失败返回原因，不扩大区域 |
| P3 | 定点抓取、持物验证、放置/递送 | 仅任务契约/接口，缺真实臂与验证链，高成本 | 单独工作区、负载、碰撞与持物验证；接触和交付人工边界另定；当前禁止直接进入实现 |

不建议当前纳入论文核心承诺：开门/开抽屉、楼梯/电梯、自主充电、人群跟随、对人递物、危险品处理、开放世界无限探索。没有观察到这些能力所需的执行器、传感器、验证和权限链。

## 5. 如何少干预而保持明确人工边界

### 5.1 任务前置授权代替机械重复确认

已有导航可以一次展示并确认完整动作序列与备选，这就是最直接的低干预收益。未来观察任务可预先限定：房间集合、对象类别、总时长、最大视点数、普通失败重试预算、禁止区域、数据保存范围，以及停止条件。预算数值要由试验选择，本报告不把任何新数值描述成现行配置。

只有落在授权范围且通过确定性安全校验的普通下一步才能自动执行。未知新接触动作、新区域、扩大预算或改变目标仍需新的授权。不能为了指标好看删除现有书桌停靠二次确认；若后续研究要评估减少它，必须先证明统一安全站位验证和授权语义，并在仿真/离线阶段比较。

### 5.2 按失败原因决定下一步

| 事件 | 自动处理建议 | 人工边界 |
|---|---|---|
| 语言含糊、对象重名 | 利用已知目录给 2–3 个明确选项；能只读查询则先查询 | 不让模型猜一个房间后移动 |
| 普通 Nav2 拒绝/abort | 仅使用已预览的一次备选；其他恢复策略需单独实现 | 无备选或备选失败停止并报告 |
| 观测质量差/短暂遮挡 | 有界重拍或换预授权安全站位 | 超预算报告未能确认，不无限循环 |
| 地图变化、定位/TF/传感器安全失效 | 取消、保持 gate 停止、等待真实 goal 终态 | 人确认环境/定位恢复后显式 rearm，并新建任务 |
| 操作员停止、取消未终结、进程重启未解决任务 | 保留不可自动恢复状态 | 不自动解锁、不自动重放，即使后续 ready 恢复 |
| 抓取、持物掉落风险、物理接触 | 当前仅作为未来研究 | 独立硬件安全/急停与接触任务授权，不由模型解释覆盖 |

软件零命令不是物理零速度或制动距离证明。`SETTLING` 等待零输出是有价值的执行条件，但不能替代轮速/运动测量和硬件安全。room-navigation 当前 `mode:=hardware` 明确未实现；所有 P0 运动现阶段都应先按既有仿真能力理解。

### 5.3 可复用原语的建议契约

未来每个原语统一提供：输入类型与版本、前置条件、有限预算、成功证据、失败类型、取消/终态语义。建议最小集合：`resolve_goal`、`navigate_named`、`settle`、`observe`、`scan_bounded`、`detect_candidates`、`filter_reachable_viewpoints`、`verify_target`、`report_evidence`、`cancel_and_drain`。这些是研究接口建议，不是当前已存在 API。

把“目标存在/位置/类别”与“下一安全动作”分开：感知可以不确定，运动验证必须确定。记忆至少保存 map digest、room revision、传感器时间、位姿、图像/点云证据引用、实例身份与置信依据；地图变动使空间记录失效，过期记录只可用于提出复查候选。

## 6. 毕业论文基线、实验与指标

### 6.1 可回答的研究问题

- RQ1：任务级一次确认，相比逐步发目标，能否在安全条件相同的前提下降低人工操作且保持完成率？
- RQ2：按房间语义先验排序，相比固定顺序/距离优先，是否减少找到目标前的路程和观察次数？
- RQ3：带时效的实例记忆和有限复查，相比每次重新搜索，能否降低干预，同时避免陈旧记忆导致的假成功？
- RQ4：确定性约束和有界备选是否减少无效动作与异常后的人工改计划？

### 6.2 公平且能落地的基线

| 基线 | 内容 | 控制条件/用途 |
|---|---|---|
| B0 逐步 GUI 操作 | 同样的房间目录、目标点、Nav2、安全 gate，人工逐个提交 | 测人工步骤成本；不把操作员经验差异解释成算法提升 |
| B1 确定性模板 | 固定语法或人工给出的正确结构化序列，一次确认 | 与模型编排隔离语言理解因素；现有 fixture 仅可用于协议/执行评测 |
| B2 受限语言编排 | 现有 schema+校验+确认，调用已授权模型（未来实验） | 同一指令集，比 exact-match/等价计划准确率、澄清和拒绝率；本轮无 live model 成绩 |
| B3 固定搜索路线 | 同一观察器、目标验证器、预算，按固定房间顺序 | 作为跨房间搜索可解释基线 |
| B4 语义排序+有界搜索 | 用语义先验排房间，仍由硬约束过滤站位 | B3/B4 仅改变排序，不同时更换感知模型和地图 |
| B5 新鲜度记忆+复查 | 最近位置优先，再按相同搜索策略补查 | 与无记忆比较；专门加入物品移动与地图变更场景 |

消融只去除研究项，如语义排序、记忆、普通失败备选；不得在真实系统关闭 gate/急停/取消保护作为消融。schema 无校验的危险输出仅做离线“会否被拒绝”统计，不能执行。

### 6.3 指标定义

| 指标 | 建议定义 | 防止误读 |
|---|---|---|
| 任务族覆盖 | 达到预注册成功标准的不同任务族数量 | 不按指令变体、房间数或按钮数充数 |
| SR | 完整满足该任务全部成功谓词的任务数 / 全部发起任务数 | 含失败、拒绝、超时；合法但模糊指令与不可执行指令另外分层 |
| 无运行中干预成功率 | 首次授权后，无人工选择/重发/接管且完整成功的比例 | 首次确认仍计入总人工成本，不能叫完全无人系统 |
| 人工干预 | 每任务：初始确认数、澄清数、运行中接管数、恢复/rearm 数、人工活跃秒数 | 配置/标注/调参时间另列；等待机器不算人工活跃时间 |
| 任务吞吐量 | 成功任务数 / 系统运行小时；并列报告成功任务数 / 人工活跃小时 | 若人工时间为零报告 N/A 或原始计数，不除零；受任务难度影响 |
| 导航 SR、到点误差、路径效率 | 每段 SR；到点 XY 误差；SPL 或任务路线效率 | 不用导航成功代替搜索/抓取成功；SPL 不惩罚原地转圈和等待，应同时报时间/转角 |
| 搜索效率 | 首次经证据验证目标的时间/路程、观察站数、预算耗尽率 | 目标不存在单独统计；“未发现”不等于“不存在” |
| 语义精度 | 目标类/实例正确率，假成功率、歧义澄清正确率 | 几何 quality 不作语义概率；同一物体多个 mask 不作多个 TP |
| 库存 P/R/F1 | 人工冻结的一对一物理实例匹配；附重复率、未命名率 | 先定义实例粒度与范围；无可审计实例表时 P/R 为 N/A，不报伪精确值 |
| 安全/恢复 | 不安全目标拒绝率；违规动作数；停止→零命令/取消终态延迟分别记录；异常恢复成功率 | 软件延迟不等于实车停止距离；安全事件为硬约束，不与任务数加权抵消 |
| 资源成本 | 每任务模型调用数、推理延迟、CPU/内存峰值与观测处理耗时 | 离线工作站产物不等于 Pi 5 可实时部署 |

单目标 SPL 参考 Habitat 原始实现：`S_i * L_i / max(L_i, P_i)`，再按 episode 平均，L 为最短可行路径长，P 为实际路径长，S 为成功指示。[E2] 对按指定顺序访问多点任务，可将各段参考最短路径相加作为路线效率的分母基准，但必须命名为本项目的多段指标，不冒称官方 ObjectNav SPL；多终点选择、返回起点和零长度路线需预先固定计分约定。短路程/原地任务以时间及成功率为主。

### 6.4 最小实验方案（P）

优先在相同预建房屋地图和离线 RGB-D 序列上进行，不必新装大仿真框架。建议任务矩阵包含：单/多房间、短/长路线、固定/任意朝向、存在/不存在/多实例目标、观测清晰/遮挡、普通不可达/安全失效，以及停止发生在发送未接受/运动中/等待/取消中。每条任务配人工核定的成功谓词和期望拒绝条件。

语言集同时包含单句、多步、别名、歧义、越界请求与格式攻击；按任务/场景划分开发与保留测试集，不能只把同一句改写后随机分割。实验顺序和路线顺序平衡，固定地图/代码/模型版本、阈值和预算，记录随机种子；建议条件允许时每条件至少 10 次重复作为起步采样计划，实际置信区间较宽时明确报告，不宣称统计充分。SR 可报二项置信区间，耗时/路径用中位数和分布；未成功样本保留超时成本。

建议事件记录字段：episode_id、task family、条件/版本、授权与澄清、action 开始/接受/终态、失败类型、观察证据、停稳证据、人工事件、最终成功谓词、总时长/路径。仿真 truth 只进入评分器，不进入 planner、perception 或控制回路。

## 7. 历史证据如何使用

### 7.1 当前本地导航评分文件

**H：**`artifacts/room-scored-final-validation/metrics.json` 记录 `room-1 → room-2 → room-3 → mian` 四次到达，最大 truth XY 误差 `0.12946331047572585 m`，共 2397 个 telemetry 样本；所有记录的到点误差 ≤0.4 m。前三次到点附近样本有非零角速度命令，文件注明 10 Hz 样本捕获 Nav2 result 时刻而非内部 settling 瞬间，最终样本为零。它支持“存在一条四房间路线评分记录”，不能证明全部房间路线可靠、无碰撞、停止时间上界或真实模型语言理解。

`docs/room-navigation.md` 另描述较早 smoke 的往返误差 5.6 cm、观察到的停止到零命令 16 ms、26 tests + 2 subtests 等。这是另一个历史实验，不与本轮 38 tests 或四房间评分合并成同一运行成绩。本轮没有启动 ROS 复现任何这些数据。

### 7.2 感知评测资产

**H：**`artifacts/perception-dev/reviews/B06-inventory-independent-review.md` 明确把 GT 标为待最终人工确认的草案，指出物体边界/命名粒度、重复碎片、实例与 overlay 对应不足；不能以 FARM/OVIR/Open3DIS 原始条目数当作真实物体计数或宣称已达到 80% 识别率。该文件末尾补充修正早期 OpenFusion loader 失败结论：后来已有官方 TSDF 几何产物，但 inventory 仍 N/A，因为默认管线没有持久物理实例输出。

因此近期最有效工作不是再罗列更多大模型：先固定少量可审计的物理实例、每个实例的支持帧和 mask、类别标准、重复合并规则，再用现有 `evaluate_inventory.py` 统一评分。该脚本已有 `recall_target_met >= 0.8` 标志，但它只是条件判断，不是系统达到目标的证据，也不自动检查 GT 是否最终人工冻结。

### 7.3 抓取证据边界

**S：**`ros2_ws/src/soarm_fake/soarm_fake/fake_mission_server.py:14,47` 是 `VisualizationPreview`。它明确不执行导航/抓取，返回 `result.success = False`，即使 action 使用 `handle.succeed()` 结束。因此论文的任务成功必须读取业务结果和持物证据，不能只看 ROS action 终态。mission policy 的 null 安全阈值、`delivery_after_grasp` 与 `place_at_second_location` 排除项进一步说明配送不能算当前已有能力。
