# Research: Household dialogue-driven visual-semantic navigation

## Summary
The closest literature already covers the major building blocks: language-indexed spatial maps (VLMaps), open-vocabulary multi-view object graphs (ConceptGraphs), hierarchical room/object graphs (HOV-SG), scenario and referring-expression navigation (SOON and REVERIE), and uncertainty-driven human interaction (CoIN). The defensible thesis slice is therefore an experimentally isolated combination: relation evidence and multi-view support for selecting among candidate instances, followed by safety-filtered, reachable observation-view selection and fresh visual verification. That is a research hypothesis, not an established novelty claim.

The existing notes at [`/home/gxxl/soarm-car-companion-validation/docs/research/companion-visual-navigation-sources.md`](/home/gxxl/soarm-car-companion-validation/docs/research/companion-visual-navigation-sources.md) and [`/home/gxxl/soarm-car-companion-validation/docs/research/companion-visual-navigation-design.md`](/home/gxxl/soarm-car-companion-validation/docs/research/companion-visual-navigation-design.md) correctly constrain the work to relation/multiview grounding plus reachable observation selection, with Nav2/FAST-LIO retained as infrastructure.

## Findings
1. **VLMaps (Huang et al., ICRA 2023)** fuses pretrained vision-language features into a 3D reconstruction and supports natural-language indexing of the map. Its official implementation expects RGB, metric depth, camera pose and calibration, making it a direct semantic-map baseline, but its core contribution is language-to-spatial retrieval rather than explicit relational instance disambiguation or active terminal verification. [Paper](https://arxiv.org/abs/2210.05714) [Official code](https://github.com/vlmaps/VLMaps)

2. **ConceptGraphs (Gu et al., 2023, arXiv:2309.16650)** builds an open-vocabulary 3D scene graph from posed RGB-D sequences using 2D foundation-model outputs and multi-view association. It is the closest reusable representation for the proposed A1: candidate objects can carry fused observations and spatial relations. Adding an object graph or multi-view fusion alone is not novel. The project is principally a mapping/perception/planning representation, not a demonstrated equal-budget policy for selecting reachable verification viewpoints on a custom mobile base. [Paper](https://arxiv.org/abs/2309.16650) [Project](https://concept-graphs.github.io/) [Official code](https://github.com/concept-graphs/concept-graphs)

3. **HOV-SG (Werby et al., RSS 2024)** introduces a hierarchical open-vocabulary 3D scene graph spanning building/floor/room/object levels for language-grounded navigation in large, multi-story environments. This directly overlaps room constraints and hierarchical semantic retrieval; a room/object hierarchy should be treated as a baseline or implementation choice, not a claimed contribution. The proposed distinction is the evaluation of relation evidence and reachable view choice under the local robot’s geometry and budget. [RSS paper](https://www.roboticsproceedings.org/rss20/p077.html) [Project](https://hovsg.github.io/) [Official code](https://github.com/hovsg/HOV-SG)

4. **CoIN (Taioli et al., ICCV 2025, pp. 18781–18792)** defines Collaborative Instance Object Navigation: the agent searches an unknown environment and actively resolves target-instance uncertainty through open-ended human dialogue while minimizing interaction. This is a direct overlap for asking questions when the candidate distribution is uncertain. Consequently, “ask the user when uncertain” is not sufficient novelty. A useful boundary is to hold dialogue fixed/text-only or use CoIN-style interaction as a comparison, while measuring the independent effect of relation/multiview evidence and physical observation selection. [CVF paper page](https://openaccess.thecvf.com/content/ICCV2025/html/Taioli_Collaborative_Instance_Object_Navigation_Leveraging_Uncertainty-Awareness_to_Minimize_Human-Agent_Dialogues_ICCV2025_paper.html) [Official code](https://github.com/intelligolabs/CoIN) [Project](https://intelligolabs.github.io/CoIN/)

5. **SOON (Zhu et al., CVPR 2021)** formalizes Scenario Oriented Object Navigation, where language describes a target in a broader scene context, and provides a graph-based exploration baseline. It is relevant to relation/context language and search, but its benchmark assumptions and simulator/action setup are not the same as a Gazebo custom robot with a local occupancy map and explicit final confirmation. Use its task framing as related work, not direct metric comparability. [CVPR paper](https://openaccess.thecvf.com/content/CVPR2021/papers/Zhu_SOON_Scenario_Oriented_Object_Navigation_With_Graph-Based_Exploration_CVPR_2021_paper.pdf) [Official code](https://github.com/ZhuFengdaaa/SOON) [Project](https://scenario-oriented-object-navigation.github.io/)

6. **REVERIE (Qi et al., CVPR 2020, pp. 9982–9991)** evaluates remote embodied visual referring expressions: language refers to an object in an indoor environment and the agent must navigate and ground it. It supplies a mature referring-expression/navigation comparator and official code, but is a precollected simulator benchmark with different observations and action abstractions. It supports the claim that language-plus-context object grounding is established; it does not directly test physical reachable viewpoint planning. [CVPR paper page](https://openaccess.thecvf.com/content_CVPR_2020/html/Qi_REVERIE_Remote_Embodied_Visual_Referring_Expression_in_Real_Indoor_Environments_CVPR_2020_paper.html) [Official code](https://github.com/YuankaiQi/REVERIE)

7. **ZSON (Majumdar et al., NeurIPS 2022)** presents zero-shot object-goal navigation using multimodal goal embeddings, transferring from ImageNav rather than using object-goal demonstrations. It is a useful semantic-search/navigation baseline for category-like language goals, but it does not supply explicit scene-graph relations, object-instance identity persistence, or a reachable observation-set objective. Porting the full training stack to Gazebo is likely disproportionate; a frozen image/text embedding nearest-candidate baseline is feasible and should share inputs with A1. [NeurIPS paper](https://proceedings.neurips.cc/paper_files/paper/2022/file/d0b8f0c8f79d3a621af945cafb669f4b-Paper-Conference.pdf) [Official code](https://github.com/gunagg/zson)

8. **HM3D-OVON (Yokoyama et al., IROS 2024)** extends ObjectNav to open-vocabulary household categories, reporting more than 15,000 instances over 379 categories in HM3D-derived scenes. It is a useful future public benchmark and vocabulary reference, but it does not make the existing Gazebo house a benchmark, and its scene/data terms and simulator integration must be handled separately. Do not compare a custom relation/instance-confirmation success number to standard ObjectNav without defining a new metric. [Paper](https://arxiv.org/abs/2409.14296) [Official code/data repository](https://github.com/naokiyokoyama/ovon)

9. **Habitat ObjectNav evaluation (Habitat Challenge 2020–2022)** defines Success around stopping within 1 m of an instance of the target category and oracle-viewability, and uses SPL for efficiency. This is an essential metric baseline, but the standard task permits any instance of a category and oracle visibility; the proposed task names a particular instance via relations and requires a new observation confirmation. Report navigation-to-safe-view success separately from fresh visual target confirmation, and define shortest paths to a legal observation-view set rather than to object centroids. [Challenge specification](https://aihabitat.org/challenge/2022/) [SPL documentation](https://aihabitat.org/docs/habitat-lab/habitat.tasks.nav.nav.SPL.html)

## Feasible Gazebo baselines and experiment boundaries

- **B0 semantic nearest candidate:** one frozen image/text encoder or existing ConceptGraphs candidate embedding; choose the highest similarity candidate, then navigate to the nearest collision-free pose. Use the same detector, map, route planner and final confirmation as all methods.
- **B1 relation-only reranker:** parse target, attributes, room and relations into structured constraints; score observed relation edges and retain explicit `unknown` for missing evidence. Compare against B0 on unique, same-class, occluded, absent and contradictory cases.
- **B2 multiview-only reranker:** aggregate support over decorrelated viewpoints/trajectory segments, with depth/pose quality penalties. This isolates whether improvement comes from evidence diversity rather than repeated adjacent frames.
- **A1 relation + multiview:** combine B1 and B2 with weights frozen on a development split. Do not call the score a probability without calibration.
- **A2 reachable observation selection:** generate candidate poses around the selected object; hard-filter footprint collision, occupancy, path reachability, map identity/revision and transform freshness; rank remaining views by visibility/occlusion proxy, expected information gain and path cost. Compare nearest-safe, fixed-order viewpoints, random-safe, and the learned/proposed utility under identical path, observation, model-call and time budgets.
- **A1+A2 closed loop:** after arrival, require a new settled RGB-D frame to confirm the specified instance. Permit bounded re-observation or report unknown/failure. A Nav2 success alone is not task success.

Existing ROS interfaces are references only. The furnished AWS scene requires a new sensor-derived map and verified transforms; the older house_floorplan occupancy map is not interchangeable. Before scoring, independently verify RGB-depth registration, camera intrinsics/extrinsics, metric units, time synchronization, camera-to-map transform, map identity/revision and legal base footprint. Gazebo hidden labels may be used only for offline oracle diagnostics, never by the deployed selector. Habitat/OVON migration is optional and should be a later external comparison, not a prerequisite.

Recommended primary metrics are instance Top-1/MRR and abstention/error rate (grounding), confirmed-target success (not merely arrival), legal-view success, path length/time, number of observations/model calls, and collision/teleoperation events. Use SPL only when the shortest path to the legal observation-view set is known; standard ObjectNav SPL is not directly transferable. Split by layout/scene, not adjacent frames, and use paired seeds/tasks across B0, A1, A2 and A1+A2.

## Gaps
The literature search does not establish that relation-plus-multiview reranking with reachable-view utility is novel; novelty requires a direct comparison against the active-perception preprints and any updated 2025–2026 releases. No runtime, GPU, ROS/Gazebo compatibility, or reproduced benchmark result was measured here. The official repositories also do not imply permissive licenses for every dataset, checkpoint, or scene asset; check each license before acquisition or release.
